# 维护手册

面向后续接手的人（或 AI）：讲清楚系统怎么跑、数据在哪、改哪里、别踩哪些坑。

## 1. 架构

```
浏览器 ──加载静态页──> Cloudflare Pages (public/*.html)
   │
   └──supabase-js (HTTPS)──> Supabase (PostgreSQL + PostgREST + RLS)
```

- 没有后端服务器、没有构建步骤、没有 npm 运行时依赖。
- 数据访问全部由浏览器直接调 Supabase REST 接口（`@supabase/supabase-js@2` 走 CDN）。
- 安全边界依赖 Supabase RLS：当前策略为「任何持 publishable key 的人可读写」。属于内网/小团队场景的取舍，若要公网暴露请改成登录鉴权。

## 2. 数据模型

| 表 | 用途 | 关键列 |
|----|------|--------|
| `materials` | 会议材料主表 | `file_name`、`file_type`、`meeting_title`、`meeting_date`(date)、`meeting_type`(存 key)、`meeting_department`、`uploader`、`wps_url`、`version`、`tags`(逗号分隔文本)、`uploaded_at`(timestamptz)、`is_final` |
| `leader_notes` | 领导备注 | `material_id`(FK→materials, ON DELETE CASCADE)、`content` |
| `meeting_types` | 会议类型字典 | `key`(唯一，入库值)、`label`(界面显示)、`sort` |
| `departments` | 部门字典 | `name`(唯一)、`sort` |
| `uploaders` | 提交人字典 | `name`(唯一)、`department` |
| `tags` | 标签字典 | `name`(唯一)、`color`、`sort` |

注意：
- `materials.tags` 是**文本**（`"重要,待办"`），不是数组；前端 `split(',')`。
- `meeting_types` 的入库值是英文 `key`，中文只用于显示，因此前端必须加载字典做 `key → label` 映射。
- 删除材料时 `leader_notes` 由数据库外键级联删除，前端不需要手动清理。

## 3. 用户端 `public/index.html`

| 位置 | 作用 |
|------|------|
| ~493 行 | `SUPABASE_URL` / `SUPABASE_KEY` 配置 |
| `loadData()` | 并行拉取 materials / leader_notes / meeting_types，构建 `allFiles` 与 `leaderNotes` |
| `getFilteredFiles()` | 组合筛选：会议类型 + 部门 + 标签 + 提交人 + 搜索词 |
| `renderRecentFiles()` | 首页渲染。标题三态：有搜索词→「搜索结果」；有筛选→「筛选结果」；都没有→「最近文件」且只取前 10 条 |
| `renderDrawer()` / `renderDrawerContent()` | 「所有文件」页：左侧分类抽屉（类型/部门/标签）+ 右侧列表 |
| `switchPage()` | 首页 / 所有文件在同一文档内切换，底部 Tab 固定 |
| `openNoteModal()` / `saveNote()` / `deleteNote()` | 备注新增、编辑（回显原文）、清空即视为无备注 |
| `openWpsLink()` | `window.open(url, '_blank', 'noreferrer')` 打开 WPS |

CSS 关键点：`.home-page, .all-files-page { display:none }`，仅 `.active` 显示；所有文件页为 `display:flex; height:calc(100vh - 48px - 56px)`，保证底部栏不被遮挡。

## 4. 管理端 `public/admin.html`

| 位置 | 作用 |
|------|------|
| ~479 行 | Supabase 配置 |
| `loadReferenceData()` | 一次性加载 4 张字典表，填充下拉框与标签选择器 |
| `loadMaterials()` | 加载材料列表并渲染（含搜索防抖） |
| `openRecordModal()` / `saveRecord()` | 新增/编辑材料；`leader_note` 单独 upsert 到 `leader_notes` |
| `confirmDeleteRecord()` | 删除材料（级联删除备注） |
| `renderTags/Depts/Types/Uploaders()` + `open*Modal/save*/delete*` | 四类字典的增删改查 |
| `exportData()` | 前端导出数据 |

表单必填项：`file_name`、`meeting_date`、`meeting_type`、`meeting_department`、`file_type`、`uploader`、`wps_url`；`meeting_title` 非必填。

## 5. 常见问题

**Q：用户端一直「加载中」/ 提示网络错误**
检查 `public/*.html` 里的 `SUPABASE_URL`、`SUPABASE_KEY` 是否属于同一个项目；打开浏览器控制台看 `loadData` 是否有报错。历史坑：`esc()` 曾对数字型 `id` 直接调 `.replace` 导致整页崩，现版本已用 `String()` 兜底。

**Q：文件类型显示 OTHER**
优先取数据库 `file_type` 字段；仅在字段为空时才从文件名后缀推断。录入时请确保 `file_type` 正确。

**Q：WPS 打开报 `referer_host not match whitelist`**
WPS 分享链接校验来源域名。必须 no-referrer 打开（见 `openWpsLink`），不要改回 `<a href>` 或普通 `window.open`。

**Q：改了代码但页面没变**
Cloudflare 有缓存，硬刷新（Ctrl/Cmd + Shift + R）；并确认部署的是 `public/` 目录、且部署成功。

**Q：`/admin.html` 返回 308**
Cloudflare Pages 的 clean-URL 行为，会自动跳到 `/admin`，属正常现象。

**Q：想换数据库**
执行 `database/init.sql` 建表，然后替换两个 HTML 里的 URL/KEY，重新部署即可，业务代码无需改动。

## 6. 恢复与迁移

1. 新 Supabase 项目执行 `database/init.sql`。
2. `scripts/backup.sh` 备份旧库 → 需要时用 Supabase 控制台 Table Editor 或 REST 接口按表导入 JSON。
3. 替换前端配置 → `bash scripts/deploy.sh` 发布；生产域名不变。
